The Problem

When do SVL quantities go wrong?

Several common Odoo scenarios leave stock valuation layers with incorrect quantities or costs — and there's no built-in tool to fix them in bulk.

💱

Cost Changed After Moves

You updated standard_price on a product, but historical SVLs still reflect the old cost. Inventory valuation is now wrong for past periods.

📥

Data Migration Errors

After migrating from another system or Odoo version, SVL quantities don't match the actual stock moves they're linked to.

🔧

Manual Corrections Gone Wrong

A previous fix attempt left SVLs in an inconsistent state that's hard to untangle one by one.

📊

Reports Don't Match Reality

Inventory valuation report shows numbers that don't match stock on hand, with no clear audit trail of what went wrong.

How It Works

Recommended workflow

Follow these steps to fix SVLs safely on any database.

Update the Product Cost

Set the product's cost field to the correct value. Changing cost on the product form alone only creates a new forward-looking SVL — it leaves old ones wrong.

Open the Fixer Wizard

Go to Inventory → Operations → Fix SVL Quantities. Select products, set date range if needed.

Run Dry Run First

Tick "Dry Run (Preview Only)" and click Run Fixer. Review the summary table — products affected, value delta, final values. Confirm it's what you expect.

Apply the Fix

Untick Dry Run and run again. The module creates a backup, applies changes in batches, and shows a live results table. Errors trigger automatic rollback.

Download CSV & Verify

Download the CSV for your records. Check your inventory valuation report to confirm the numbers now match expectations.

Restore If Needed

Something looks wrong? Go to Inventory → Configuration → SVL Fixer Backups, open the relevant backup, and click Restore This Backup.

Cost Source

Two modes for different situations

Choose the right cost source for your specific problem.

Mode When to Use How It Works
Use Current Product Cost Your SVLs are out of sync with the product's current standard_price. You want to realign all historical SVLs to today's cost. Reads standard_price from the product form and applies it to all matching SVLs in the selected date range.
Enter a Custom Cost You know the specific correct historical cost, but the current product price is different or unrelated to the mistake you're fixing. You type the cost directly. That exact value is applied to all matching SVLs — ignoring whatever is on the product form.

FAQ

Common questions

Does this work with AVCO (average cost) products?

The module is designed primarily for Standard Cost products. For AVCO products, the correct cost depends on the sequence of receipts — applying a single uniform cost to historical SVLs will produce incorrect average cost calculations. Use with caution on AVCO products and always run Dry Run first.

Will this affect my accounting journal entries?

The module modifies SVL records directly. It does not automatically create new journal entries to match. If SVLs are linked to posted accounting moves, your inventory valuation and GL may diverge. Review your accounting impact after any fix.

What does Dry Run actually do?

Dry Run reads all SVLs, calculates what changes would be made, and shows the full summary table — without writing a single record. No backup is created in Dry Run mode. It is purely read-only.

What happens if the run fails partway through?

The module uses transaction rollback on errors. If an exception occurs, all changes from that batch are rolled back. The backup record from before the run remains intact so you can restore the pre-run state manually.

Can I fix only SVLs from a specific period?

Yes. Use the From Date and To Date fields to filter by SVL creation date. Only SVLs created within that window will be processed. Older or newer records are untouched.

What is the Min Unit Cost Change field?

This skips SVLs where the difference between the current and correct cost is below your set amount. Useful on large catalogs to ignore rounding differences and focus only on meaningful discrepancies.

Does it track historical cost at the time of each move?

No. The module applies one cost uniformly to all selected SVLs — either the current product standard_price or a manually entered value. It does not reconstruct what the cost was at the time of each individual move.
